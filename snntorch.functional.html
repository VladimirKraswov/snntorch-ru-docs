snntorch.functional

snntorch.functional реализует общие арифметические операции, применяемые к спайковым нейронам, такие как функции потерь и регуляризации, квантование состояния и т.д.

Как использовать функционал

Для использования snntorch.functional вы присваиваете состояние функции переменной, а затем вызываете эту переменную.

Пример:

import snntorch as snn
import snntorch.functional as SF

net = Net().to(device)
optimizer = torch.optim.Adam(net.parameters(), lr=lr, betas=betas)
loss_fn = SF.ce_count_loss()  # apply cross-entropy to spike count

spk_rec, mem_rec = net(input_data)
loss = loss_fn(spk_rec, targets)

optimizer.zero_grad()
loss.backward()

# Weight Update
optimizer.step()

static backward(ctx, grad_output)[source]

Определите формулу для дифференцирования операции с обратным режимом автоматического дифференцирования.

Эта функция должна быть переопределена всеми подклассами. (Определение этой функции эквивалентно определению vjp функции.)

Она должна принимать контекст ctx в качестве первого аргумента, за которым следует столько выходных данных, сколько forward() возвращено (None будет передано для не-тензорных выходов прямой функции), и она должна вернуть столько тензоров, сколько было входов в forward(). Каждый аргумент является градиентом по данному выходу, и каждое возвращаемое значение должно быть градиентом по соответствующему входу. Если вход не является тензором или является тензором, не требующим градиентов, вы можете просто передать None в качестве градиента для этого входа.

Контекст можно использовать для получения тензоров, сохраненных во время прямого прохода. Он также имеет атрибут ctx.needs_input_grad в виде кортежа булевых значений, представляющих, нуждается ли каждый вход в градиенте. Например, backward() будет иметь ctx.needs_input_grad[0] = True если первый вход в forward() нуждается в градиенте, вычисленном по выходу.

static forward(ctx, spk_rec, spk_count, device='cpu')[source]

Определите прямой проход пользовательской функции autograd.

Эта функция должна быть переопределена всеми подклассами. Существует два способа определить forward:

Использование 1 (Объединенный forward и ctx):

@staticmethod
def forward(ctx: Any, *args: Any, **kwargs: Any) -> Any:
    pass

  • Он должен принимать контекст ctx в качестве первого аргумента, за которым следует любое количество аргументов (тензоров или других типов).

  • Смотрите combining-forward-context для получения дополнительных сведений

Использование 2 (Раздельные forward и ctx):

@staticmethod
def forward(*args: Any, **kwargs: Any) -> Any:
    pass


@staticmethod
def setup_context(ctx: Any, inputs: Tuple[Any, ...], output: Any) -> None:
    pass

  • Forward больше не принимает аргумент ctx.

  • Вместо этого вы также должны переопределить torch.autograd.Function.setup_context() staticmethod для обработки настройки ctx объекта. output является выходом forward, inputs являются кортежем входов в forward.

  • Смотрите extending-autograd для получения дополнительных сведений

Контекст может использоваться для хранения произвольных данных, которые могут быть затем извлечены во время обратного прохода. Тензоры не должны храниться непосредственно на ctx (хотя в настоящее время это не обеспечивается для обратной совместимости). Вместо этого тензоры должны сохраняться либо с помощью ctx.save_for_backward() если они предназначены для использования в backward (эквивалентно, vjp) или ctx.save_for_forward() если они предназначены для использования for in jvp.

class snntorch.functional.loss.ce_count_loss(population_code=False, num_classes=False, reduction='mean', weight=None)[source]

Базовые классы: LossFunctions

Потери по количеству спайков (кросс-энтропия).

Спайки на каждом временном шаге [num_steps x batch_size x num_outputs] накапливаются и затем передаются через функцию потерь кросс-энтропии. Этот критерий объединяет log_softmax и NLLLoss в одной функции. Потери кросс-энтропии поощряют правильный класс генерировать спайки на всех временных шагах и стремятся подавить спайки неправильных классов.

Потери по количеству спайков (Cross Entropy Count Loss) сначала накапливают спайки, а затем применяют потери кросс-энтропии только один раз. Напротив, потери по скорости (Cross Entropy Rate Loss) применяют функцию кросс-энтропии на каждом временном шаге.

Пример:

import snntorch.functional as SF

# if not using population codes (i.e., more output neurons than
there are classes)
loss_fn = ce_count_loss()
loss = loss_fn(spk_out, targets)

# if using population codes; e.g., 200 output neurons, 10 output
classes --> 20 output neurons p/class
loss_fn = ce_count_loss(population_code=True, num_classes=10)
loss = loss_fn(spk_out, targets)
Параметры:

  • population_code (bool, необязательный) – Указывает, применяется ли популяционный код, т.е., количество выходов больше количества классов. По умолчанию False

  • num_classes (int, необязательный) – Количество выходных классов должно быть указано, если population_code=True. Должен быть делителем количества выходных нейронов, если включен популяционный код. По умолчанию False

Возвращает:

Loss

Тип возврата:

torch.Tensor (один элемент)

class snntorch.functional.loss.ce_max_membrane_loss(reduction='mean', weight=None)[source]

Базовые классы: LossFunctions

Потери кросс-энтропии по максимальному мембранному потенциалу. При вызове значение максимального мембранного потенциала для каждого выходного нейрона сэмплируется и передается через функцию потерь кросс-энтропии. class snntorch.functional.loss.ce_rate_loss(population_code=False, num_classes=False, reduction='mean', weight=None)[source]

Базовые классы: LossFunctions

Потери скорости спайков с перекрёстной энтропией. При вызове спайки на каждом временном шаге последовательно передаются через функцию потерь перекрёстной энтропии. Этот критерий объединяет log_softmax и NLLLoss в одной функции. Потери накапливаются по временным шагам для получения итоговых потерь. Потери перекрёстной энтропии поощряют правильный класс срабатывать на всех временных шагах и направлены на подавление срабатывания неправильных классов.

Потери скорости перекрёстной энтропии применяют функцию перекрёстной энтропии на каждом временном шаге. В отличие от этого, потери количества перекрёстной энтропии сначала накапливают спайки, а затем применяют потери перекрёстной энтропии только один раз.

Пример:

import snntorch.functional as SF

loss_fn = SF.ce_rate_loss()
loss = loss_fn(outputs, targets)

class snntorch.functional.loss.ce_temporal_loss(inverse='negate', reduction='mean', weight=None)[source]

Базовые классы: object

Временные потери перекрёстной энтропии.

Вычисляются потери перекрёстной энтропии для «инвертированного» времени первого спайка каждого выходного нейрона [batch_size x num_outputs]. «Инверсия» применяется таким образом, что максимизация значения правильного класса уменьшает время первого спайка (т.е. более ранний спайк).

Варианты инверсии включают: inverse='negate' который применяет (-1 * output), или inverse='reciprocal' который берёт (1/output).

Обратите внимание, что производная каждого времени спайка по отношению к спайку df/dU недифференцируема для большинства классов нейронов и установлена на знаковую оценку -1. Т.е. увеличение мембранного потенциала вызывает пропорционально более раннее время срабатывания.

Метки индексов передаются как цель. Чтобы указать точное время спайка, используйте mse_temporal_loss вместо этого.

Примечание: После времени спайков с указанными целями штраф за последующие спайки не применяется.

Пример:

import torch
import snntorch.functional as SF

# correct classes aimed to fire by default at t=0, incorrect at
final step
loss_fn = ce_temporal_loss()
loss = loss_fn(spk_out, targets)
Параметры:

inverse (str, необязательный) – Указывает, как инвертировать выходные данные перед применением перекрёстной энтропии. Либо масштабировать на (-1 * x) с помощью inverse='negate' или взять обратную величину (1/x) с помощью inverse='reciprocal'. По умолчанию negate

Loss

class snntorch.functional.loss.mse_count_loss(correct_rate=1, incorrect_rate=0, population_code=False, num_classes=False, reduction='mean', weight=None)[source]

Базовые классы: LossFunctions

Потери количества спайков среднеквадратической ошибки. При вызове общее количество спайков накапливается за время для каждого нейрона. Целевое количество спайков для правильных классов устанавливается в (num_steps * correct_rate), а для неправильных классов (num_steps * incorrect_rate). class snntorch.functional.loss.mse_temporal_loss(target_is_time=False, on_target=0, off_target=-1, tolerance=0, multi_spike=False, reduction='mean', weight=None)[source]

Временные потери среднеквадратической ошибки.

Время первого спайка каждого выходного нейрона [batch_size x num_outputs] измеряется относительно желаемого времени спайка с помощью функции потерь среднеквадратичной ошибки (Mean Square Error Loss). Обратите внимание, что производная каждого времени спайка по спайку df/dU недифференцируема для большинства классов нейронов и устанавливается как оценка знака -1. То есть увеличение мембранного потенциала вызывает пропорционально более раннее время срабатывания.

Потери временной среднеквадратичной ошибки (Mean Square Error Temporal Loss) могут учитывать множественные спайки путем установки multi_spike=True. Если фактическое время спайка достаточно близко к целевому времени спайка в пределах заданного допуска, например, tolerance = 5 временных шагов, то оно не вносит вклад в потери.

По умолчанию метки индексов передаются в качестве цели. Чтобы разрешить передачу времени спайка(ов) для выходного(ых) нейрона(ов), установите target_is_time=True.

Примечание: После времени спайка с указанными целями штраф за последующие спайки не применяется. Чтобы исключить последующие спайки, следует применить дополнительную цель.

Пример:

import torch
import snntorch.functional as SF

# default takes in idx labels as targets
# correct classes aimed to fire by default at t=0, incorrect at t=-1 (final time step)
loss_fn = SF.mse_temporal_loss()
loss = loss_fn(spk_out, targets)

# as above, but correct class fire @ t=5, incorrect at t=100 with a
# tolerance of 2 steps
loss_fn = SF.mse_temporal_loss(on_target=5, off_target=100, tolerance=2)
loss = loss_fn(spk_out, targets)

# as above with multiple spike time targets
on_target = torch.tensor((5, 10))
off_target = torch.tensor((100, 105))
loss_fn = SF.mse_temporal_loss(on_target=on_target,
off_target=off_target, tolerance=2)
loss = loss_fn(spk_out, targets)

# specify first spike time for 5 neurons individually, zero tolerance
target = torch.tensor((5, 10, 15, 20, 25))
loss_fn = SF.mse_temporal_loss(target_is_time=True)
loss = loss_fn(spk_out, target)
Параметры:

  • target_is_time (bool, необязательный) – Указывает, задается ли цель как время спайков (True) или как индексы нейронов (False). По умолчанию False

  • on_target (int (или итерабельный для нескольких int, если multi_spike=True), необязательно) – Время спайка для правильных классов (только если target_is_time=False). По умолчанию 0

  • off_target (int (или итерабельный для нескольких int, если multi_spike=True), необязательно) – Время спайка для неправильных классов (только если target_is_time=False). По умолчанию -1, т.е. последний временной шаг

  • tolerance (int, необязательный) – Если расстояние между временем спайка и целью меньше указанного допуска, то оно не вносит вклад в потери. По умолчанию 0.

  • multi_spike (bool, необязательный) – Указывает, есть ли множественные спайки в цели. По умолчанию False

static backward(ctx, grad_output)[source]

Определите формулу для дифференцирования операции с обратным режимом автоматического дифференцирования.

Эта функция должна быть переопределена всеми подклассами. (Определение этой функции эквивалентно определению vjp функции.)

Она должна принимать контекст ctx в качестве первого аргумента, за которым следует столько выходных данных, сколько forward() возвращено (None будет передано для не-тензорных выходов прямой функции), и она должна вернуть столько тензоров, сколько было входов в forward(). Каждый аргумент является градиентом по данному выходу, и каждое возвращаемое значение должно быть градиентом по соответствующему входу. Если вход не является тензором или является тензором, не требующим градиентов, вы можете просто передать None в качестве градиента для этого входа.

Контекст можно использовать для получения тензоров, сохраненных во время прямого прохода. Он также имеет атрибут ctx.needs_input_grad в виде кортежа булевых значений, представляющих, нуждается ли каждый вход в градиенте. Например, backward() будет иметь ctx.needs_input_grad[0] = True если первый вход в forward() нуждается в градиенте, вычисленном по выходу.

static forward(ctx, input_, levels)[source]

Определите прямой проход пользовательской функции autograd.

Эта функция должна быть переопределена всеми подклассами. Существует два способа определить forward:

Использование 1 (Объединенный forward и ctx):

@staticmethod
def forward(ctx: Any, *args: Any, **kwargs: Any) -> Any:
    pass

  • Он должен принимать контекст ctx в качестве первого аргумента, за которым следует любое количество аргументов (тензоров или других типов).

  • Смотрите combining-forward-context для получения дополнительных сведений

Использование 2 (Раздельные forward и ctx):

@staticmethod
def forward(*args: Any, **kwargs: Any) -> Any:
    pass


@staticmethod
def setup_context(ctx: Any, inputs: Tuple[Any, ...], output: Any) -> None:
    pass

  • Forward больше не принимает аргумент ctx.

  • Вместо этого вы также должны переопределить torch.autograd.Function.setup_context() staticmethod для обработки настройки ctx объекта. output является выходом forward, inputs являются кортежем входов в forward.

  • Смотрите extending-autograd для получения дополнительных сведений

Контекст может использоваться для хранения произвольных данных, которые могут быть затем извлечены во время обратного прохода. Тензоры не должны храниться непосредственно на ctx (хотя в настоящее время это не обеспечивается для обратной совместимости). Вместо этого тензоры должны сохраняться либо с помощью ctx.save_for_backward() если они предназначены для использования в backward (эквивалентно, vjp) или ctx.save_for_forward() если они предназначены для использования for in jvp.

snntorch.functional.quant.state_quant(num_bits=8, uniform=True, thr_centered=True, threshold=1, lower_limit=0, upper_limit=0.2, multiplier=None)[source]

Обучение с учётом квантования (Quantization-Aware Training) с состояниями спайковых нейронов.

Примечание: для квантования весов мы рекомендуем использовать Brevitas или другую существующую библиотеку, совместимую с PyTorch.

Равномерное и неравномерное квантование может применяться в различных режимах путём указания uniform=True.

Допустимые уровни квантования могут быть центрированы относительно 0 или порога путём указания thr_centered=True.

upper_limit и lower_limit укажите долю, насколько допустимые уровни выходят выше и ниже положительного и отрицательного порога/ Например, upper_limit=0.2 означает, что максимальное допустимое состояние на 20% выше значения, указанного в threshold.

Пример:

import torch
import snntorch as snn
from snntorch.functional import quant

beta = 0.5
thr = 5

# set the quantization parameters
q_lif = quant.state_quant(num_bits=4, uniform=True, threshold=thr)

# specifying state_quant applies state-quantization to the
# hidden state(s) automatically
lif = snn.Leaky(beta=beta, threshold=thr, state_quant=q_lif)

rand_input = torch.rand(1)
mem = lif.init_leaky()

# forward-pass for one step
spk, mem = lif(rand_input, mem)

Примечание: Обучение с учётом квантования направлено на моделирование сети с пониженной точностью, но само по себе не ускоряет модели с низкой точностью. Скрытые состояния по-прежнему представляются как значения полной точности для совместимости с PyTorch. Для ускорения производительности или при ограниченной памяти модель следует экспортировать в нижележащий бэкенд.

Параметры:

  • num_bits (int, необязательный) – Количество битов для квантования переменных состояния, по умолчанию 8

  • uniform (Bool, необязательный) – Применяет равномерное квантование, если указано, неравномерное, если не указано, по умолчанию True

  • thr_centered (Bool, необязательный) – Для неравномерного квантования указывает, должны ли допустимые состояния быть центрированы (плотно сгруппированы) вокруг порога вместо нуля, по умолчанию True

  • порог (float, необязательный) – Указывает порог, по умолчанию 1

  • lower_limit (float, необязательный) – Указывает, насколько ниже (-threshold) может быть самое низкое допустимое состояние, т.е. (-threshold - threshold*lower_limit), по умолчанию 0

  • upper_limit (float, необязательный) – Указывает, насколько выше (threshold) может быть самое высокое допустимое состояние, т.е. (threshold + threshold*upper_limit), по умолчанию 0.2

  • множитель (float, необязательный) – Для неравномерных распределений укажите основание экспоненты. Если None, подходящее значение устанавливается внутренне на основе num_bits, по умолчанию None

class snntorch.functional.probe.OutputMonitor(net: Module, instance: Any = None, function_on_output: Callable = <function OutputMonitor.<lambda>>)[source]

Базовые классы: BaseMonitor

Монитор для записи выходных спайков каждого конкретного слоя нейронов (например, Leaky) в сети. Все выходные данные записываются в self.record в виде данных типа ‘’list’’. Вызовите self.enable() или self.disable() чтобы включить или отключить монитор. Вызовите self.clear_recorded_data() чтобы очистить записанные данные.

Пример:

import snntorch as snn
from snntorch.functional import probe

import torch
from torch import nn

class Net(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(8, 4)
        self.lif1 = snn.Leaky()
        self.fc2 = nn.Linear(4, 2)
        self.lif2 = snn.Leaky()

    def forward(self, x_seq: torch.Tensor):
        x_seq = self.fc1(x_seq)
        x_seq = self.lif1(x_seq)
        x_seq = self.fc2(x_seq)
        x_seq = self.lif2(x_seq)
        return x_seq

net = Net()

monitor = probe.OutputMonitor(net, instance=snntorch.Leaky())

with torch.no_grad():
    y = net(torch.rand([1, 8]))
    print(f'monitor.records={monitor.records}')
    print(f'monitor[0]={monitor[0]}')
    print(f'monitor.monitored_layers={monitor.monitored_layers}')
    print(f"monitor['lif1']={monitor['lif1']}")

  • net (nn.Module) – Модель сети (либо обернутая в контейнер Sequential, либо в виде класса)
